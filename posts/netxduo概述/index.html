NETXDUO概述

June 13, 2025
#Ethernet

简介

Azure RTOS NetX Duo 是一个双 IPv4 和 IPv6 TCP/IP 网络堆栈，专为深度嵌入式、实时和物联网应用而设计。它具有多种功能。除了 TCP/IP IPv4/IPv6 网络堆栈外，它还提供了一个实现标准加密和哈希方法的加密库，以及一个支持安全网络连接的 TLS/DTLS 库。

  • NetX Duo 核心提供完整的 TCP/IP IPv4 IPV6 兼容堆栈，具有 3 种类型的 API：TCP/IP、UDP/IP 和 RAW API。
  • Crypto 核心实现了用于保护连接和交换加密数据的常见加密密码套件和哈希算法：AES、3DES、HMAC、RSA、SHA1、SHA224、SHA256、SHA384、SHA512、MD5、HMAC-SHA1 等（每种算法都有自己的实现文件 .c 和头文件 .h，方便应用程序选择和集成所需的算法）。
  • TLS 核心实现了安全连接 API。它基于 Crypto 核心和 NetX Duo 核心，支持 TLS 和 DTLS 协议及其不同变体。（TLS 1.0、TLS 1.2、TLS 1.3）。

它还支持X509公共签名证书协议。

  • 附加协议是一组预先支持的网络应用协议，可简化网络功能在最终用户应用程序中的集成。主要支持的协议如下：DHCP、DNS、mDNS、HTTP、HTTPS、FTP、TELNET、MQTT、SMTP、POP3、SNTP、SNMP 等。

NetXDuo 集成在 STM32 微控制器

NetX Duo 可以在任何网络硬件上运行，例如以太网、WiFi 模块、蜂窝调制解调器等。它需要一个低级驱动程序来在已选定的物理层和 NetX Duo 核心请求（初始化、传输数据、接收数据）之间进行交互。

为了实现 NetX Duo 堆栈和所需 PHY 之间的交互，软件架构应遵循下面的树状结构。

目前支持以下硬件配置：

  • ehernet：根据主板的不同，支持多种以太网 PHY 外部组件：
    • lan8742/
      • nx_stm32_phy_driver.c ：10/100BT LAN8742 PHY的 PHY 驱动程序源文件，使用Drivers/BSP/Components/lan8742下的 BSP 组件（在 X-CUBE-AZRTOS-H7 包中提供）。
    • rtl8211/
      • nx_stm32_phy_driver.c ：10/100/1000BT RTL8211 PHY的 PHY 驱动程序源文件，使用Drivers/BSP/Components/rtl8211下的 BSP 组件（在 STM32N6 Cube 包中提供）。
    • nx_stm32_eth_driver.c：使用 STM32 ETH IP 的 MAC 级驱动源文件。
    • nx_stm32_eth_driver.h：MAC驱动程序的头文件。
    • nx_stm32_phy_driver.h：以太网PHY驱动程序的通用头文件。

  • template ：包含新网络驱动程序源模板的目录
    • nx_custom_driver.c：根据硬件进行定制的 NetXDuo 驱动程序源代码。
    • ethernet/nx_stm32_phy_driver.c：以太网 PHY 代码的模板。
  • WiFi：此支持专门针对支持旁路模式的 WiFi 模块和提供 MXCHIP EMW3080 模块的 STM32 板。

要启用此连接模式，用户应使用 mx_wifi_conf.h 文件中的标志对其进行配置。

  • “mx_wifi_conf_template.h”：此应用程序级配置文件应复制到应用程序源代码树中，并重命名为mx_wifi_conf.h。然后根据应用程序和驱动程序的需求进行定制。

必须考虑以下主要配置标志：

"MX_WIFI_USE_SPI" - 使用 SPI 而不是 UART 与 MXCHIP 通信。
"MX_WIFI_NETWORK_BYPASS_MODE" - 使用旁路模式而不是 AT 命令。
"MX_WIFI_TX_BUFFER_NO_COPY" - 不需要复制 TX 缓冲区。
"WIFI_SSID" - 定义接入点的名称。
"WIFI_PASSWORD" 定义接入点的密码。
  • “Nx_driver_framework.c”：NetX 驱动程序的默认处理入口点，用作 NetXDuo 核心和 EMW3080 Phy 联络之间的接口。
  • “Nx_driver_framework.h”：包含驱动程序定义和数据结构的驱动程序头文件。
  • “Nx_driver_emw3080.c”：用于链接 nx_driver_framework 和 Mxchip 模块之间的命令的 Phy 接口。
  • “Nx_driver_emw3080.h”：驱动程序头文件，包含驱动程序定义和数据结构。
  • “Mx_wifi_azure_rtos.c”：包含 mxchip 所需的所有 tx 和 nx 分配。

经过低层配置后，当创建 IP 实例时，应用程序代码会调用它：

/*通过链接 nx 网络驱动程序创建 IP 实例 */

/* 以太网 STM32H7 示例：  */
  ret = nx_ip_create(&EthIP, "NetX IP Instance 0", NULL_IP_ADDRESS, NULL_IP_ADDRESS, 
&EthPool, nx_stm32_eth_driver, pointer, IP_MEMORY_SIZE, DEFAULT_PRIORITY);

/* STM32U5 WIFI 示例： */
ret = nx_ip_create(&IpInstance, "Main IP Instance", NULL_IP_ADDRESS, NULL_IP_ADDRESS, 
& AppPool, nx_driver_emw3080_entry, pointer, MEMORY_SIZE, DEFAULT_PRIORITY);

已知限制

  • BSD API 支持并非完全兼容。这可能会影响旧版应用程序的可移植性。更多详情请参阅 NetX Duo 官方文档。

如何使用 NetX Duo

下表介绍了使用 NetX Duo 所需的主要 API：（更多详细信息和完整的 API 描述可参阅 NetX Duo 官方文档。

函数名称简短描述
nx_udp_socket_receive()从 UDP 远程客户端接收数据包
nx_udp_socket_create()创建 UDP 套接字
nx_udp_socket_bind()将 UDP 套接字绑定到端口
nx_tcp_socket_receive()从 TCP 远程客户端接收数据包
nx_tcp_socket_disconnect()断开 TCP 服务器套接字
nx_tcp_socket_create()创建 TCP 套接字
nx_tcp_server_socket_unaccept()拒绝 TCP 服务器套接字
nx_tcp_server_socket_relisten()设置服务器套接字以再次监听
nx_tcp_server_socket_listen()设置 TCP 套接字进行监听
nx_tcp_server_socket_accept()接受 TCP 远程客户端套接字连接

使用 NetX Duo 的主要步骤是：

  • 在 MX 的 app_azure_rtos_config.h 中定义 NX_APP_MEM_POOL_SIZE。例如，100 KB。
#define NX_APP_MEM_POOL_SIZE 102400
  • 在 app_azure_rtos.c 中创建一个大小为 NX_APP_MEM_POOL_SIZE 的字节池"nx_app_byte_pool"
if (tx_byte_pool_create(&tx_app_byte_pool, "Tx App memory pool", tx_byte_pool_buffer, TX_APP_MEM_POOL_SIZE) != TX_SUCCESS)
{}

然后在 MX_NetXDuo_Init 中，用户应该遵循此例程（分配、创建）。

  • 从字节池分配内存：
/* Allocate the memory for packet_pool.  */
if (tx_byte_allocate(byte_pool, (VOID **) &pointer, NX_PACKET_POOL_SIZE, TX_NO_WAIT) != TX_SUCCESS)
{
    return TX_POOL_ERROR;
}
  • 创建池 AppPool：
/* Create a packet pool.  */
status = nx_packet_pool_create(&pool_0, "NetX Main Packet Pool", SAMPLE_PACKET_SIZE,
                               (UCHAR *)sample_pool_stack , sample_pool_stack_size);
  • 然后创建并配置属于已创建的池的 IP 实例。
  • 根据目标应用程序启用所需的 NetX Duo 组件：
函数名称简短描述
nx_arp_enable()启用地址解析协议（AutoIP 协议需要 ARP）（需要内存分配）
nx_icmp_enable()Ping 必需
nx_udp_enable()启用 UDP 流量（DNS 和 DHCP 需要 UDP）
nx_tcp_enable()启用 TCP 流量

迁移到 NetX Duo

为了将开发项目从现有网络堆栈（例如 LwIP 或其他）迁移到 NetX Duo，目前尚无直接的自动化流程。然而，API 之间通常存在一些相似之处，这些相似之处在执行此任务时可能会有所帮助。下面提供了一些比较示例。

功能NetXDuoLwIP
DHCP服务c /* create the DHCP client */ ret = nx_dhcp_create(&DHCPClient, &IpInstance, "DHCP Client"); /* Create an IP @ change callback */ ret = nx_ip_address_change_notify(&IpInstance, ip_address_change_notify_callback, NULL); /* start DHCP client */ ret = nx_dhcp_start(&DhcpClient);/* Start DHCP process to get IP@*/ dhcp_start(netif); /* Get Client data */ dhcp = (struct dhcp *)netif_get_client_data(netif, LWIP_NETIF_CLIENT_DATA_INDEX_DHCP); /* Wait until getting DHCP data */ if (dhcp_supplied_address(netif)) { DHCP_state = DHCP_ADDRESS_ASSIGNED; }
HTTP 服务/* Create the HTTP Server. */ status = nx_http_server_create(&HTTPServer, "WEB HTTP Server", &IPInstance, &ram_disk, pointer, SERVER8STQCK, &WebServerPool, NX_NULL, webserver_request_notify_callback); /* Start the WEB HTTP Server. */ status = nx_http_server_start(&HTTPServer); /* Web Server callback when a new request from a web client is triggered */ static UINT webserver_request_notify_callback(NX_WEB_HTTP_SERVER *server_ptr, UINT request_type, CHAR* resource, NX_PACKET *packet_ptr); /* Extract the client request type from the client request */ nx_web_http_server_type_get(server_ptr, server_ptr->nx_web_http_server_request_resource, temp_string, &string_length);/* Create a new TCP connection handle */ conn = netconn_new(NETCONN_TCP); /* Bind to port 80 (HTTP) with default IP address */ err = netconn_bind(conn, NULL, 80); /* Put the connection into LISTEN state */ netconn_listen(conn); /* Accept any incoming connection */ accept_err = netconn_accept(conn, &newconn); /* Read the data from the port, blocking if nothing yet there. We assume the request (the part we care about) is in one netbuf */ recv_err = netconn_recv(conn, &inbuf); /* Get the data pointer and length in netbuf */ netbuf_data(inbuf, (void**)&buf, &buflen);

STM32 NetX Duo 应用

下图显示了使用以太网的 STM32H7 示例的项目架构和主要应用程序文件。

STM32 软件包提供以下一组应用程序（不同产品和主板所支持的应用程序列表可能有所不同）：

应用简短描述
Nx_TCP_Echo_Server演示如何开发 NetX TCP 服务器以使用 NetX TCP 套接字 API 与远程客户端通信。
Nx_TCP_Echo_Client演示如何开发 NetX TCP 客户端以使用 NetX TCP 套接字 API 与远程服务器通信。
Nx_UDP_Echo_Server演示如何开发 NetX UDP 服务器以使用 NetX UDP 套接字 API 与远程客户端通信。
Nx_UDP_Echo_Client演示如何开发 NetX UDP 客户端以使用 NetX UDP 套接字 API 与远程服务器通信。
Nx_WebServer演示如何开发基于 Web HTTP 服务器的应用程序。本示例旨在使用 Web HTTP 服务器加载存储在 SD 卡或 OCTOSPI 内存中的文件和静态/动态网页。代码提供了构建兼容 Web HTTP 服务器所需的所有功能。
Nx_MQTT_Client演示如何使用 MQTT 协议以支持 TLS v1.2 的加密模式在客户端和服务器之间交换数据。
Nx_SNTP_Client演示如何开发 NetX SNTP 客户端并连接 STNP 服务器以获取时间更新。
