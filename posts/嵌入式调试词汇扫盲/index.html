嵌入式调试词汇扫盲

June 15, 2025
#debug

现如今嵌入式计算机的调试技术已经很丰富了，有许许多多的软件和硬件去帮助程序员找出嵌入式软件上的逻辑漏洞以及嵌入式硬件上的缺陷等等。但是很多东西在概念上就存在大量的混用(ps:说难听点就是乱用)，不知道是英文翻译的问题还是开发人员的水平问题，各种词汇就很让人摸不着头脑，最常见也是最广泛的就是调试技术了。

常见词汇及其含义

中文英文含义
调试器Debugger调试器是一个笼统的概念，通常用来查看代码在运行时正在执行的操作， 可以逐步浏览代码并查看变量中存储的值，可以设置变量的监视，以查看值何时发生更改，可以检查代码的执行路径，等等。在嵌入式软件中的区别就是本地调试还是跨平台调试，如果是本地调试的话，调试器本质上是一个软件；如果是跨平台的话在软件的基础上，还得有一套硬件的支持，而这个硬件就是下面的仿真器。
监视器Monitor与真实硬件交互。 监控器需要连接并控制实际的物理 MCU 芯片。它在运行时观察和修改 MCU 内部的真实状态（寄存器、内存、外设）。从一些角度来说，所谓的监视器是属于调试器的，它是调试器的软件基础，就是跨平台调试器中所指得软件之一。最常见的软件就是OpenOCD、J-Link Software、Segger Ozone 等等。可以看到上面提到的软件有的是命令行工具(CLI)有的是有可视化界面的，其中 OpenOCD 在 VSC 中可以配合Cortex-Debug 插件使用可视化界面。
仿真器Emulator也叫做调试探针（如 ST-Link, J-Link, DAPLink）连接到 MCU 的专用调试接口（如 JTAG, SWD）。
模拟器Simulator软件虚拟硬件。 模拟器在 PC 上运行一个软件模型来模仿目标 MCU 的行为，不需要连接任何物理硬件。它模拟 CPU 内核、内存（Flash/RAM）以及（部分）外设的逻辑行为。常见模拟器有 Keil µVision Simulator、QEMU 等。
下载器/烧录器/编程器Programmer一般简写成 PG，Programmer 主要修改只读存储器中的程序，Programmer 通常与计算机连接，再配合编程软件使用。如果功能上和 Monitor 一样这样的硬件通常也叫做 Debug Adapter ，但是在某些一些系统中专指烧写外部 FLASH 的设备并不是调试探针。

嵌入式软件调试

上图中可以知道整个调试系统用得到的相关软硬件。其中图中的 GDB 是 GUN 软件系统社区提供的调试工具，同 GCC 配套组成了一套完整的开发环境。GDB 是调试过程中必不可少的软件，通常和 OpenOCD 一起使用，OpenOCD 连接上 Emulator 后会在计算机中监听某一个端口如 3333，GDB 连接该端口后就可以下达相关指令对目标 MCU 进行调试。

软件调试过程

假设已经编译好目标文件 blinky.elf (实现板载 LED 灯每隔一秒亮灭的功能)

a. STLink USB 插入电脑，在 VSC 中新建终端输入：

openocd -f interface/stlink-v2.cfg -f target/stm32f1x.cfg

b.再次新建终端输入：

arm-none-eabi-gdb

c. 加载目标文件。在 arm-none-eabi-gdb 终端输入：

file <path to elf>/blinky.elf

d. 连接上openocd。在 arm-none-eabi-gdb 终端输入：

target remote :3333

e. 重置MCU。在 arm-none-eabi-gdb 终端输入：

monitor reset halt

f. 写入(烧录)。在 arm-none-eabi-gdb 终端输入：

load

g. 运行。在 arm-none-eabi-gdb 终端输入：

continue

此时板载 LED 灯按照程序每隔一秒亮灭。

另外还可以下达打断点、单步调试等指令，具体见相关文档教程。
